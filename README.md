## 常用命令

### 目录操作

| 命令 | 用途 |
|------|------|
| `cd 路径`(change directory) | 进入目录，`cd ..` 返回上一级，`cd ~` 回主目录 |
| `ls`(list)（Windows CMD 用 `dir`） | 列出当前目录下的文件 |
| `mkdir 名称`（make directory） | 新建文件夹 |
| `rmdir 名称`（remove directory） | 删除空目录 |
| `pwd`(print working directory) | 显示当前所在路径（打印当前工作目录） |

### 路径符号、常用选项与通配符

| 写法 | 类别 | 含义 |
|------|------|------|
| `.` | 路径符号 | 当前目录 |
| `..` | 路径符号 | 当前目录的上一级目录 |
| `~` | 路径符号 | 当前用户的主目录（Windows 上一般是 `C:\Users\用户名`） |
| `/` | 路径符号 | 根目录（bash 里 `D:\OCgame` 写成 `/d/OCgame`） |
| `-a` | `ls` 的选项 | 显示包括隐藏文件在内的所有文件 |
| `-l` | `ls` 的选项 | 以列表形式显示文件的详细信息 |
| `-h` | `ls` 的选项 | 文件大小显示得更易读（KB / MB） |
| `*` | 通配符 | 匹配 0 个或多个任意字符 |
| `?` | 通配符 | 匹配单个字符（半角问号，不是全角 `？`） |

举例：`ls -la` 列出全部文件（含隐藏文件）的详细信息；`ls *.html` 列出所有 HTML 文件；`cd ..` 回到上一级目录。



### Git 常用命令

## 贪吃蛇的两个开发阶段

整个游戏按"先能玩、再让它自己玩"的顺序推进，两个阶段各自带着可复现的验证方法。

### 阶段一：做出"能自己玩"的版本

**怎么实现**

- 用 `<canvas>` 画一个 22×22 的格子棋盘（四周一圈是墙，中间 20×20 是活动区），蛇、食物、金色奖励果、得分飘字全部用像素矩形一块块拼出来。
- 一个主循环串起"更新"和"渲染"：`requestAnimationFrame` 每帧重画，逻辑推进用固定时间步 + 累加器（`acc += dt; while (acc >= speed) step()`），掉帧也不瞬移、速度稳定。
- 输入有三条通道：键盘（方向键 / WASD / 空格暂停 / R 重开 / T 切主题）、触屏滑动、移动端十字键；方向先进一个最多 2 格的队列，杜绝快速连按时原地掉头。
- 玩法闭环：吃食物得分，5 秒窗口内连续吃叠加连击倍率（最高 ×5），每吃满 5 个食物放出一个金色奖励果（+50），越吃越快、升级再加速；撞墙或咬到自己即结束，结束后结算本局。
- 计分与战绩：最高分 / 上一局 / 局数常驻显示、新一局不清零；最近 10 局战绩列表 + 完整列表弹层；深色 / 浅色主题一键切换；这些都用 localStorage 持久化。

**怎么验证**

- 人工验收：直接打开 `snake/index.html`（或线上 https://xborn14.github.io/xborn/snake/），键盘和触屏各玩一局，检查移动、吃分、连击、加速、结束结算，以及刷新后战绩与主题是否还在。
- 自动化自检：打开 `snake/index.html?autotest`，页面会跑一组确定性断言——摆好一条蛇，手动驱动 `step()` 依次吃下食物和奖励果，逐项核对"食物重新生成 / 基础分 = 10 / HUD 同步 / 第 5 个食物触发奖励果 / 奖励果 +50 / 飘字数量"，再核对战绩追加、主题即时切换与刷新保留、撞墙结束自动追加战绩等，最后把结果写进页面标题：`AUTOTEST-PASS` 表示全过，`AUTOTEST-FAIL` 后跟一串 0/1 用来定位是哪一步失败。

### 阶段二：让 AI 来玩（自动演示）

**怎么实现**

- 入口：点「AI 演示」按钮，或打开带 `?autoplay` 的地址。`startAI()` 会把蛇放到一条预设环路的起点，并把步速调到 15ms 让演示快速跑。
- 决策器 `aiStep()` 每次要走一步时回答"下一步往哪走"，分两档策略：蛇长 ≤ 20 时用 BFS 搜到食物的最短路径，再把整条路径预演一遍、并用一次洪水填充确认走完还能碰到尾巴且留得下一整条蛇身的活动空间，三层都过才抄近路；蛇长 > 20 就切到汉密尔顿回路，沿"每格恰好经过一次"的闭合环路稳扎稳打，永不撞墙、不咬自己，理论上能占满全屏。
- 与阶段一共用同一套 `step()`：AI 只负责"选方向"，移动、吃分、死亡判定都复用阶段一的代码，所以 AI 演示和真人玩走的是完全相同的规则。

**怎么验证**

- 看自动演示：打开 `snake/index.html?autoplay`（默认冲到 2000 分自动定格；加 `&nocap` 则一直玩到自然死亡），观察它能长时间不撞墙、不断吃分。
- 量化证据：`?autoplay` 模式下页面会把最终得分写进标题 `AUTOPLAY-SCORE <分数>`，方便脚本截图或断言"AI 确实能活着玩到指定分数"。
- 定格看结果：打开 `?auto` 会自动开局并暂停，把棋盘冻住，便于截图确认蛇和食物都正确画了出来。
- 共享逻辑自检：`?autotest` 里对战绩、主题等断言的覆盖同样作用于 AI 共享的那套代码（撞墙结束自动追加战绩、最高分/上一局不清零等）。

## 贪吃蛇里几处关键逻辑

游戏是单文件 HTML，全部逻辑都在 `snake/index.html`。下面挑几处"看上去简单、其实有讲究"的地方，用大白话讲清楚它为什么这么写。

### 1. AI 演示为什么不会把自己走进死路

手动玩时你一眼看不出三步以后的局面，AI 演示靠的是**走之前先在脑子里预演一遍**，一共三层判断：

1. **先找最短路线**：从蛇头用 BFS（广度优先搜索）搜到食物，得到一条最短路径。
2. **把整条路预演一遍**：在内存里复制一条"假蛇"，按规则一步步往前走（吃到食物的那步不缩尾，其余每步缩尾）；中途只要撞到自己的身体，这条路就直接作废。
3. **最关键的一层：走完之后还有没有退路**：预演结束后，从新的蛇头做一次"洪水填充"（flood fill，往四个方向漫开数能到的格子），要求同时满足两件事——**能碰到自己的尾巴**，并且**能到达的空格数不少于蛇身长度**。

第 3 层才是"避开死路"的核心。只保证"下一步不撞"是远远不够的：蛇可能一步步越走越窄，最后把自己圈进死角。要求"走完还留得下一整条蛇身的活动空间"，等于强制它别把自己关起来。三层全过，AI 才真的转向走这条路；任何一层不过，就退到下面的保底策略。

### 2. 保底策略：沿着一条"汉密尔顿回路"爬

`buildCycle()` 在棋盘内部的 20×20 格上拼出一条**闭合环路**：从起点出发，每个格子恰好经过一次，最后回到起点。它值得记的原因：

- 蛇只要沿环路一格格往前爬，**永远不会撞墙、也不会咬到自己**——环上每格只走一次，路线是固定的。
- 20×20 = 400 格，所以理论上它能长到占满整屏。
- 代价是绕远路、吃食物慢，所以只当兜底：**蛇长 ≤ 20 时用第 1 条的 BFS 抄近路；一旦超过 20，就放弃捷径、回到环上稳扎稳打**。这是很典型的工程取舍——短蛇灵活，值得冒险；长蛇一失手满盘皆输，只能走"绝对安全但慢"的路。
- 万一环路的下一格被身体占了（正常不该发生），它再退一步：朝四个能走的方向各做一次小范围洪水填充，挑"能到达格子最多"的那个方向。

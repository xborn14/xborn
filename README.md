## 常用命令

### 目录操作

| 命令 | 用途 |
|------|------|
| `cd 路径`(change directory) | 进入目录，`cd ..` 返回上一级，`cd ~` 回主目录 |
| `ls`(list)（Windows CMD 用 `dir`） | 列出当前目录下的文件 |
| `mkdir 名称`（make directory） | 新建文件夹 |
| `rmdir 名称`（remove directory） | 删除空目录 |
| `pwd`(print working directory) | 显示当前所在路径（打印当前工作目录） |

### 路径符号、常用选项与通配符

| 写法 | 类别 | 含义 |
|------|------|------|
| `.` | 路径符号 | 当前目录 |
| `..` | 路径符号 | 当前目录的上一级目录 |
| `~` | 路径符号 | 当前用户的主目录（Windows 上一般是 `C:\Users\用户名`） |
| `/` | 路径符号 | 根目录（bash 里 `D:\OCgame` 写成 `/d/OCgame`） |
| `-a` | `ls` 的选项 | 显示包括隐藏文件在内的所有文件 |
| `-l` | `ls` 的选项 | 以列表形式显示文件的详细信息 |
| `-h` | `ls` 的选项 | 文件大小显示得更易读（KB / MB） |
| `*` | 通配符 | 匹配 0 个或多个任意字符 |
| `?` | 通配符 | 匹配单个字符（半角问号，不是全角 `？`） |

举例：`ls -la` 列出全部文件（含隐藏文件）的详细信息；`ls *.html` 列出所有 HTML 文件；`cd ..` 回到上一级目录。



### Git 常用命令

| 命令 | 用途 |
|------|------|
| `git init` | 当前目录初始化为仓库 |
| `git clone 地址` | 克隆远程仓库到本地 |
| `git status` | 查看当前改动状态 |
| `git add 文件名` | 暂存改动（`.` 表示全部） |
| `git commit -m "说明"` | 提交到本地仓库 |
| `git push` | 推送到远程仓库 |
| `git pull` | 拉取远程最新代码 |
| `git log --oneline -5` | 查看最近 5 条提交记录 |
| `git branch` | 查看分支 |
| `git checkout 分支名` | 切换分支 |
| `git merge 分支名` | 合并分支到当前 |
| `git remote -v` | 查看远程仓库地址 |
| `git remote set-url origin 新地址` | 修改远程地址 |
| `git diff` | 查看未暂存的改动 |

## 贪吃蛇里几处关键逻辑

游戏是单文件 HTML，全部逻辑都在 `snake/index.html`。下面挑几处"看上去简单、其实有讲究"的地方，用大白话讲清楚它为什么这么写。

### 1. AI 演示为什么不会把自己走进死路

手动玩时你一眼看不出三步以后的局面，AI 演示靠的是**走之前先在脑子里预演一遍**，一共三层判断：

1. **先找最短路线**：从蛇头用 BFS（广度优先搜索）搜到食物，得到一条最短路径。
2. **把整条路预演一遍**：在内存里复制一条"假蛇"，按规则一步步往前走（吃到食物的那步不缩尾，其余每步缩尾）；中途只要撞到自己的身体，这条路就直接作废。
3. **最关键的一层：走完之后还有没有退路**：预演结束后，从新的蛇头做一次"洪水填充"（flood fill，往四个方向漫开数能到的格子），要求同时满足两件事——**能碰到自己的尾巴**，并且**能到达的空格数不少于蛇身长度**。

第 3 层才是"避开死路"的核心。只保证"下一步不撞"是远远不够的：蛇可能一步步越走越窄，最后把自己圈进死角。要求"走完还留得下一整条蛇身的活动空间"，等于强制它别把自己关起来。三层全过，AI 才真的转向走这条路；任何一层不过，就退到下面的保底策略。

### 2. 保底策略：沿着一条"汉密尔顿回路"爬

`buildCycle()` 在棋盘内部的 20×20 格上拼出一条**闭合环路**：从起点出发，每个格子恰好经过一次，最后回到起点。它值得记的原因：

- 蛇只要沿环路一格格往前爬，**永远不会撞墙、也不会咬到自己**——环上每格只走一次，路线是固定的。
- 20×20 = 400 格，所以理论上它能长到占满整屏。
- 代价是绕远路、吃食物慢，所以只当兜底：**蛇长 ≤ 20 时用第 1 条的 BFS 抄近路；一旦超过 20，就放弃捷径、回到环上稳扎稳打**。这是很典型的工程取舍——短蛇灵活，值得冒险；长蛇一失手满盘皆输，只能走"绝对安全但慢"的路。
- 万一环路的下一格被身体占了（正常不该发生），它再退一步：朝四个能走的方向各做一次小范围洪水填充，挑"能到达格子最多"的那个方向。

### 3. 方向输入用队列，防快速连按把自己撞死

`setDir()` 并不直接改蛇的方向，而是把新方向压进一个**最多存 2 个**的队列。判断"是不是在掉头"时，比较的对象是**队列里最后一个还没执行的方向**，队列空才用当前方向。

如果偷懒拿"当前方向"去比，就会出事：蛇正在向上时，你飞快地按 左、下——按"下"的瞬间蛇还没转完，当前方向仍是上，程序会以为"下"合法；等蛇真的转过左再执行下，就变成原地掉头咬到自己。改用队列里"最后一个待执行方向"来比较，这类连按就被自动挡住了。

### 4. 固定时间步 + 累加器：速度控制的地基

主循环里是这么写的：`acc += dt; while (acc >= speed) { step(); acc -= speed; }`

- 画面由 `requestAnimationFrame` 每帧重画，**逻辑推进**则按固定的 `speed` 毫秒一次来算，两者解耦。
- 好处：掉帧或切后台回来时蛇不会"瞬移"一大段（超过 200ms 的间隔会被截断），速度也不会忽快忽慢。
- "越吃越快"就是改这个 `speed`：初始 150ms 走一步，每吃一个食物减 5ms（最低 70ms），每升一级再减 10ms（最低 60ms）。

### 5. 两个"计时器"：连击倒计时与奖励果保质期

- `comboTimer` 是个倒计时：吃到食物就重置为 5 秒，主循环里每帧减去真实流逝时间，归零则倍率复位为 1。所以倍率（最高 ×5）奖励的是**连续快吃**，慢慢吃没有加成。
- 每吃满 5 个食物放出一个金色奖励果（+50 分），它带一个 6 秒的"保质期"；渲染时发现过期就直接清掉，屏幕上不会留一个已经不能吃的目标。
- 得分公式是 `基础分 × 当前倍率`（食物 10 分），奖励果固定 50 分——所以连击状态下吃食物，通常比干等奖励果更划算。

另外两个小设计：主题只存一个键（`snake_theme`），并且在页面 `<head>` 里于首帧绘制之前就把它读回来，所以刷新不会先闪一下默认配色；战绩存在 `snake_stats_v1` 里，每局结束由 `recordRound()` 追加一条，而**AI 演示局不写入记录**，免得机器人的分数把真人的最高分和战绩冲掉。
